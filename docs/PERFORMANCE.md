# 성능·용량 기준 (동시 접속 100명)

RFP 요건: **동시 접속자 100명 기준으로 모든 기능이 정상 작동**.

## 1. 결론

경량 CRUD 성격의 문진 서비스로, **동시 100명은 아키텍처상 충분히 여유 있는 수준**이다.
아래 설정으로 처리 용량을 명시적으로 확보했고, 실제 검증용 부하 테스트(`scripts/loadtest.js`)를 제공한다.

## 2. 구간별 처리 용량

| 구간           | 처리 방식               | 100명 동시 대응                                        |
| -------------- | ----------------------- | ------------------------------------------------------ |
| 정적 프론트    | nginx 가 정적 파일 서빙 | 수천 동시 요청도 여유(정적 자산). 100명 무부담         |
| WAS(요청 처리) | 내장 Tomcat 스레드풀    | `max-threads=200` → 동시 100 요청도 절반 여유          |
| DB 커넥션      | HikariCP 풀             | `maximum-pool-size=20` (요청이 짧아 100 사용자에 충분) |
| DB             | PostgreSQL              | 기본 `max_connections=100` 이내(풀 20)로 안전          |

> 핵심: "동시 접속 100명" ≠ "동시 DB 쿼리 100개". 문진 조회/제출은 수십 ms 로 끝나므로
> 20개 커넥션 풀로 초당 수백~수천 요청을 처리한다. 스레드(200)·커넥션(20)에 모두 여유가 있다.

## 3. 적용 설정 (`server/src/main/resources/application.yml`)

모두 환경변수로 재조정 가능(운영 튜닝).

```yaml
server:
  tomcat:
    threads: { max: 200, min-spare: 20 } # 동시 요청 처리 스레드
    accept-count: 100 # 대기 큐
    max-connections: 10000
spring:
  datasource:
    hikari:
      maximum-pool-size: 20 # DB 커넥션 풀(경량 CRUD·100명 기준)
      minimum-idle: 5
      connection-timeout: 30000
```

| 환경변수             | 기본값 | 용도                     |
| -------------------- | ------ | ------------------------ |
| `TOMCAT_MAX_THREADS` | 200    | 동시 요청 처리 스레드 수 |
| `DB_POOL_MAX`        | 20     | DB 커넥션 풀 최대        |
| `DB_POOL_MIN_IDLE`   | 5      | 유휴 커넥션 최소         |

> 참고: 과거 `datasource`/`jpa` 설정이 `springdoc:` 하위로 잘못 들여쓰기되어 `spring.datasource`
> 로 인식되지 않던 문제를 바로잡았다(이 수정 없이는 커넥션 풀 튜닝 자체가 적용되지 않음).

## 4. 실제 검증 방법 (부하 테스트)

100 VU(가상 사용자)로 문진 조회/상세 흐름을 반복하며 오류율·응답시간을 측정한다.

```bash
# k6 설치 후 (https://k6.io)
BASE_URL=https://qnr.hospital.example.com k6 run scripts/loadtest.js
```

**합격 기준(스크립트 thresholds):** 오류율 < 1%, p95 응답 < 800ms. 미달 시 종료코드로 실패 표시.

시나리오: 0→100명 램프업(30s) → 100명 동시 유지(2m) → 램프다운(30s), think time 1~3초.

## 5. 용량 증설(수평 확장) 여지

100명을 크게 초과하는 상황을 대비한 확장 경로:

- **백엔드 다중 인스턴스** + nginx `upstream` 라운드로빈(무상태 JWT 인증이라 세션 고정 불필요)
- HikariCP 풀·Tomcat 스레드 상향(위 환경변수)
- DB 읽기 부하 시 커넥션 풀 확대 / 읽기 전용 복제본

## 6. 정직한 한계 명시

- 위 수치는 **경량 CRUD 부하 가정**의 용량 산정이다. 문서 변환(PDF/DOCX) 등 무거운 작업이
  동시에 몰리는 경우는 별도 산정이 필요하다(해당 작업은 프론트/워커에서 처리하도록 분리됨).
- **최종 "정상 작동" 판정은 실 배포 스택에서 `scripts/loadtest.js` 실행 결과로 확정**한다.
  (현재 저장소는 config·도구까지 준비 완료, 실행 결과는 배포 환경에서 수집)
